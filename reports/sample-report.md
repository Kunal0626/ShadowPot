## What attackers did

**These sentences describe generated data, not real attackers.** See the synthetic sample data banner above.

Across 7 days this honeypot recorded 670 sessions from 210 distinct addresses, between 2026-11-01T00:15:24.667267Z and 2026-11-07T23:51:40.013460Z. There were 5,332 login attempts, of which 152 succeeded. The most-tried credential pair was `root` / `123456`, attempted 1,625 times from 196 distinct addresses. The credential that was accepted was `root` / `123456`. This is not evidence of a compromise: a honeypot accepts whatever its configuration tells it to accept, so what this measures is which staged credential the attackers happened to find. 37 addresses came back on more than one day; the most persistent was 198.51.100.147, seen on 7 separate days across 70 sessions.

20 credential pairs were tried from five or more different addresses, which means those hosts are working from a shared list rather than each from its own. 942 shell commands were entered. The most common opening command was `uname -a`, which started 75 sessions. By the heuristic in `queries/13_bot_vs_human.sql`, the sessions that ran commands break down as 53 human-like, 99 scripted. That is a heuristic over command timing and sequence reuse, not a measurement of who was at the keyboard, and its thresholds are stated in the query. 133 file transfers were recorded, covering 82 distinct files by content hash. The most widely shared was fetched by 17 distinct addresses. Across 1 loader run, 43 lines could not be used and 123 events had an event id this project does not model. Those are broken out per run under Data quality below; no finding here accounts for them. Geolocation and network ownership are **not measured**. That would need an offline GeoIP database, which this project does not ship, and ShadowPot deliberately makes no live lookups against attacker addresses.

## Limitations

- **SYNTHETIC SAMPLE DATA.** Nothing here is a measurement of real attacker behaviour.
- **Geolocation and network ownership are not measured.** That needs an offline GeoIP database this project does not ship. ShadowPot makes no live API calls with attacker addresses, deliberately.
- **The scripted-or-hand-driven split is a heuristic.** Thresholds are in `queries/13_bot_vs_human.sql`. On synthetic data the two populations separate cleanly, which demonstrates the SQL is correct and says nothing about whether the thresholds suit real traffic.
- **A successful login is not a compromise.** Cowrie accepts whatever its configuration accepts, so successes measure which staged credential was found.
- **Unmodelled events are excluded from every total.** The event ids this project does not handle are listed in `docs/LOG_FORMAT.md` section 6, and counted under Data quality.
- **Session identifiers are unique per sensor, not globally.** Merging two honeypots' databases needs the `(sensor, session)` key; see `docs/NORMALIZATION.md` section 8.3.
